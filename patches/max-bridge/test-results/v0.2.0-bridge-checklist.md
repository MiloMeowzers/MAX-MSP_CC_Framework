# max-bridge v0.2.0 -- follow-ups checklist (Q34)

v0.2.0 adds the kill switch, DSP restore, the sample-rate guard, taps under each `dac~`, distinct error counts and `--note`. None of it is confirmed in MAX yet; this checklist is how you confirm it. Run every command from the repo root. Paste the JSON (or the `ping` output) and the exit code (`echo $?`) from each step into its Result line.

0. [ ] Setup
   - Turn the volume down: `fx-clean` plays a 440 Hz tone at 0.2, and simple-fm plays a note.
   - Close the original of any patch under test (the temp copy uses the same `send`/`receive` names).
   - Open `patches/max-bridge/generated/max-bridge.maxpat` in MAX 9.2. The enable toggle (top left) starts OFF.
   - Expect: the bridge's console is clean.
   - Result:

1. [ ] Kill switch
   - Confirm the toggle shows OFF and the layout is tidy: toggle top left with its label, no overlapping boxes, every cord flowing down.
   - Run `python3 tools/max_bridge.py ping`.
   - Expect: exit 2 and a hint that names the enable toggle.
   - Turn the toggle ON and run `python3 tools/max_bridge.py ping` again.
   - Expect: `PONG <n> ms`, exit 0. Leave the toggle ON for steps 2-6.
   - Result:

2. [ ] DSP off before the check (restore off, taps)
   - Switch DSP OFF in MAX, then run `python3 tools/max_bridge.py check patches/max-bridge/fixtures/fx-clean.maxpat --record 2 --shot`.
   - Expect: `dsp_before` 0, `dsp_stop_sent` true, DSP OFF afterwards, `verdict` clean.
   - Open the run dir's `shot.png`: the two `send~ __maxbridge_L/R` taps sit directly under `dac~`, side by side, with no overlap.
   - Result:

3. [ ] DSP on before the check (left on)
   - Switch DSP ON in MAX, then run `python3 tools/max_bridge.py check patches/max-bridge/fixtures/fx-clean.maxpat --record 2 --shot`.
   - Expect: `dsp_before` 1, `dsp_stop_sent` false, DSP still ON afterwards.
   - Is `/state/dsp` present in `events_raw`, and with which value?
   - Result:

4. [ ] Sample-rate guard
   - Set MAX's sampling rate to 44.1 k with the interface at 48 k (the v0.1.0 setup that read 478.9 Hz), then run `python3 tools/max_bridge.py check patches/max-bridge/fixtures/fx-clean.maxpat --record 3`.
   - Expect: `record.channels.L.pitch_hz` ~440, `record.seconds` ~3.0, `record.warnings` containing `sr_header_mismatch`, exit 0.
   - Paste the `/state/sr` and `/state/adsr` values from `events_raw`, `max_sr`, `record.sample_rate` and `record.header_sample_rate`.
   - Result:

5. [ ] Distinct errors
   - Run `python3 tools/max_bridge.py check patches/max-bridge/fixtures/fx-nosuchobj.maxpat`.
   - Expect: the stderr summary reads `findings: 1 distinct error(s) (...)`, and `errors_distinct` has one entry keyed `osc~: No such object`.
   - Run `python3 tools/max_bridge.py check patches/max-bridge/fixtures/fx-genfail.maxpat --settle 5`.
   - Expect: 1 distinct error with 2 occurrences (`codebox: can't assign to parameter g`); a `failed to compile` line, if MAX posts one, is a second distinct entry.
   - Paste the `obj` value of the gen~ error's `console` entry.
   - Result:

6. [ ] Note stimulus
   - Run `python3 tools/max_bridge.py check patches/simple-fm/generated/simple-fm.maxpat --record 3 --note 60 100 --note-ms 2000 --shot`.
   - Expect: the note is audible, `silent` is not flagged, the level falls after 2 s (a release tail), `note_target` is `{"kind": "notein", ...}`.
   - Afterwards `git status --porcelain patches/simple-fm` and `find patches -name '__maxbridge_*'` both print nothing.
   - Result:

7. [ ] Kill switch OFF while idle
   - Turn the toggle OFF, then run `python3 tools/max_bridge.py check patches/max-bridge/fixtures/fx-clean.maxpat`.
   - Expect: exit 2 and the summary hint naming the toggle; no window opens.
   - Result:
