# max-bridge v0.2.0 -- follow-ups checklist (Q34)

v0.2.0 adds the kill switch, DSP restore, the sample-rate guard, taps under each `dac~`, distinct error counts and `--note`. None of it is confirmed in MAX yet; this checklist is how you confirm it. Run every command from the repo root. Paste the JSON (or the `ping` output) and the exit code (`echo $?`) from each step into its Result line.

0. [done] Setup
   - Turn the volume down: `fx-clean` plays a 440 Hz tone at 0.2, and simple-fm plays a note.
   - Close the original of any patch under test (the temp copy uses the same `send`/`receive` names).
   - Open `patches/max-bridge/generated/max-bridge.maxpat` in MAX 9.2. The enable toggle (top left) starts OFF.
   - Expect: the bridge's console is clean.
   - Result: Done (2026-10-21).

1. [done] Kill switch
   - Confirm the toggle shows OFF and the layout is tidy: toggle top left with its label, no overlapping boxes, every cord flowing down.
   - Run `python3 tools/max_bridge.py ping`.
   - Expect: exit 2 and a hint that names the enable toggle.
   - Turn the toggle ON and run `python3 tools/max_bridge.py ping` again.
   - Expect: `PONG <n> ms`, exit 0. Leave the toggle ON for steps 2-6.
   - Result: Pass. Toggle OFF at load: `ping` exit 2 with the toggle hint. Toggle ON: `PONG 0.8 ms`.

2. [done] DSP off before the check (restore off, taps)
   - Switch DSP OFF in MAX, then run `python3 tools/max_bridge.py check patches/max-bridge/fixtures/fx-clean.maxpat --record 2 --shot`.
   - Expect: `dsp_before` 0, `dsp_stop_sent` true, DSP OFF afterwards, `verdict` clean.
   - Open the run dir's `shot.png`: the two `send~ __maxbridge_L/R` taps sit directly under `dac~`, side by side, with no overlap.
   - Result: Pass on rerun. `dsp_before` 0, `dsp_stop_sent` true, 440.0 Hz, 2.0 s, the taps under `dac~`. The first run hit a driver restart (rate 44100 -> 48000 -> 44100 mid-record, 0.69 s analyzed as 404 Hz), so the client now uses the rate from the recording window and flags `sr_changed_during_run` / `short_recording` (16ee8974).

3. [done] DSP on before the check (left on)
   - Switch DSP ON in MAX, then run `python3 tools/max_bridge.py check patches/max-bridge/fixtures/fx-clean.maxpat --record 2 --shot`.
   - Expect: `dsp_before` 1, `dsp_stop_sent` false, DSP still ON afterwards.
   - Is `/state/dsp` present in `events_raw`, and with which value?
   - Result: Pass. `dsp_before` 1, `dsp_stop_sent` false, DSP left on, and `/state/dsp` present in events_raw.

4. [done] Sample-rate guard
   - Set MAX's sampling rate to 44.1 k with the interface at 48 k (the v0.1.0 setup that read 478.9 Hz), then run `python3 tools/max_bridge.py check patches/max-bridge/fixtures/fx-clean.maxpat --record 3`.
   - Expect: `record.channels.L.pitch_hz` ~440, `record.seconds` ~3.0, `record.warnings` containing `sr_header_mismatch`, exit 0.
   - Paste the `/state/sr` and `/state/adsr` values from `events_raw`, `max_sr`, `record.sample_rate` and `record.header_sample_rate`.
   - Result: Pass, though not as planned: MAX started at 44100, and the driver pulled it to 48000 at 1.15 s, before recording started. The whole recording was at 48k, the header matched, and the result was 440.0 Hz and 3.0 s with no false flags.

5. [done] Distinct errors
   - Run `python3 tools/max_bridge.py check patches/max-bridge/fixtures/fx-nosuchobj.maxpat`.
   - Expect: the stderr summary reads `findings: 1 distinct error(s) (...)`, and `errors_distinct` has one entry keyed `osc~: No such object`.
   - Run `python3 tools/max_bridge.py check patches/max-bridge/fixtures/fx-genfail.maxpat --settle 5`.
   - Expect: 1 distinct error with 2 occurrences (`codebox: can't assign to parameter g`); a `failed to compile` line, if MAX posts one, is a second distinct entry.
   - Paste the `obj` value of the gen~ error's `console` entry.
   - Result: Pass after a fix: fx-nosuchobj gives 1 distinct (1 occurrence). fx-genfail with DSP on first gave 6 distinct, because each console msg was paired with the previous obj and quotes made keys differ. After fixing both (7320329b) it gives 3 distinct, 5 occurrences: can't assign x3, failed to compile genpatcher, failed to compile patcher.

6. [done] Note stimulus
   - Run `python3 tools/max_bridge.py check patches/simple-fm/generated/simple-fm.maxpat --record 3 --note 60 100 --note-ms 2000 --shot`.
   - Expect: the note is audible, `silent` is not flagged, the level falls after 2 s (a release tail), `note_target` is `{"kind": "notein", ...}`.
   - Afterwards `git status --porcelain patches/simple-fm` and `find patches -name '__maxbridge_*'` both print nothing.
   - Result: Pass. `note_target` notein (top/obj-2), pitch 261.63 Hz, peak 0.14, no flags. The RMS envelope holds at 0.115 to 2.0 s and releases to silence by 2.2 s. simple-fm untouched, no leftover copies.

7. [done] Kill switch OFF while idle
   - Turn the toggle OFF, then run `python3 tools/max_bridge.py check patches/max-bridge/fixtures/fx-clean.maxpat`.
   - Expect: exit 2 and the summary hint naming the toggle; no window opens.
   - Result: Pass on the second try (the toggle was still on the first time). Toggle OFF gives exit 2, the toggle hint, and nothing opened.

## Open questions (v0.2.0)

V1. (RESEARCH A1) Does `adstatus switch` send 0/1 out its RIGHT outlet on bang? If not, `dsp_before` falls back to the dspstate~ inference.
   - Answered by: step 3
   - Answer: Yes (step 3): `/state/dsp 1` came back on the /query bang, and also unprompted on every DSP change.

V2. (A2) Which rate does dspstate~ outlet 1 report with MAX at 44.1 k and the interface at 48 k, and does `adstatus sr` agree?
   - Answered by: step 4
   - Answer: Both report the same rate at every point, and both also report unprompted on rate changes. With MAX at 44.1k and the interface at 48k, MAX reported 44100 until the driver switched it to 48000 shortly after DSP started (steps 2 and 4). The mismatch did not persist the way it did in v0.1.0.

V3. (A3) Does dspstate~ report automatically right after `; dsp start` (a `/state/sr` before the second `/query`)?
   - Answered by: step 4
   - Answer: Yes: a `/state/sr` arrives right after DSP starts, before the second /query (steps 2-4).

V4. (A4) What is `/con/obj` for the gen~ compile error (`codebox`, `gen~`, something else)?
   - Answered by: step 5
   - Answer: `codebox` for `can't assign to parameter g`. With DSP on, MAX also posts `gen_domain` (failed to compile genpatcher) and `gen~` (failed to compile patcher) (step 5).

V5. Does the notein mirror make simple-fm sound, and does `/note 60 0 1` release it?
   - Answered by: step 6
   - Answer: Yes (step 6): middle C at 261.63 Hz, and the note-off at 2.0 s releases it to silence by about 2.2 s.

V6. (A7) Does toggle OFF drop everything (ping, check) and close listening?
   - Answered by: step 7
   - Answer: Yes (steps 1 and 7): with the toggle off, ping and check both get no answer (exit 2 with the hint). Close-listening is wired via `select 0` -> `/listen 0`; it was not observed separately.

V7. Are the taps under `dac~` visible and tidy in the screenshot (no overlap)?
   - Answered by: step 2
   - Answer: Mostly (step 2): both taps sit right under `dac~`. Cosmetic leftovers in the temp copy: the R tap's cord runs diagonally from the shared source past `dac~`, and the close-hook boxes sit clipped at the right window edge.
