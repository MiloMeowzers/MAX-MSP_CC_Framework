# max-bridge v0.3.0 -- /max-verify --live checklist (Q34)

v0.3.0 adds `check --dsp-on-load` to `tools/max_bridge.py` and the `/max-verify --live` wrapper `tools/max_verify_live.py` (quick 261021-olv). None of it is confirmed in MAX yet; this checklist is how you confirm it. Run every command from the repo root. Paste the output and the exit code (`echo $?`) from each step into its Result line.

The wrapper never switches the bridge's enable toggle and never opens the bridge patch (D-04): every toggle change below is yours.

## Open questions (v0.3.0)

W1. Does DSP-on-load surface fx-genfail's `failed to compile` lines with DSP OFF beforehand (the v0.2.0 run only saw them with DSP already on)?
   - Answered by: step 4
   - Answer: Yes. With DSP OFF beforehand, DSP-on-load surfaced `can't assign to parameter g` (x3), `gen_domain ... failed to compile genpatcher` and `gen~: failed to compile patcher`; DSP was OFF again afterwards. With DSP ON beforehand: same 3, DSP left ON.

W2. (RESEARCH A4) What is the MAX window title of an open original, saved and with unsaved edits (`<stem>`, `<stem>*`, something else)? Does the skip catch both?
   - Answered by: step 6
   - Answer: Locked: `simple-fm (presentation)`. Unlocked with an unsaved edit: `simple-fm (unlocked presentation)`. MAX shows no `*` edit marker. The skip missed the unlocked title until 869b5885 (any trailing lowercase mode group is now stripped); both are caught now.

W3. (A5) How many seconds per patch, load-only versus record (estimate: about 5 s and 9 s)?
   - Answered by: step 3
   - Answer: Record = record length + ~7.5 s (simple-fm, record 3 s: 10.75 s); load-only ~= 4.5-5 s (step 3: load-only + 3 s record = 15.5 s; step 7 dry run: 2 x 5 s record + 1 load-only = 28.4 s).

W4. Does switching the toggle OFF mid-batch abort within one load-timeout, and leave no temp window or copy behind?
   - Answered by: step 7
   - Answer: Yes, in 10.7 s (inside one 30 s load timeout), exit 2, the rest listed as not checked, temp file deleted. But the copy window stays open and DSP stays on: the close and the DSP restore cannot pass the closed gate. The abort hint now says to close `__maxbridge_<stem>` without saving and check DSP (a4e17423).
