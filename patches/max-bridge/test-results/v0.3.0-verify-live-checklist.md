# max-bridge v0.3.0 -- /max-verify --live checklist (Q34)

v0.3.0 adds `check --dsp-on-load` to `tools/max_bridge.py` and the `/max-verify --live` wrapper `tools/max_verify_live.py` (quick 261021-olv). None of it is confirmed in MAX yet; this checklist is how you confirm it. Run every command from the repo root. Paste the output and the exit code (`echo $?`) from each step into its Result line.

The wrapper never switches the bridge's enable toggle and never opens the bridge patch (D-04): every toggle change below is yours.

0. [ ] Setup
   - Turn the volume down: simple-fm plays a note and `fx-clean` / `fx-dc` play for a few seconds.
   - Close the originals of the patches under test and any unrelated patch: console posts from other open patches are attributed to the patch under test.
   - Open `patches/max-bridge/generated/max-bridge.maxpat` in MAX 9.2. The enable toggle (top left) starts OFF.
   - Expect: the bridge's console is clean.
   - Result: pending

1. [ ] Toggle OFF: the live check skips, the static report stays intact
   - With the toggle OFF, run `/max-verify --live` on the active project.
   - Expect: the static report and its Summary counts exactly as without `--live`, then `live check skipped: <hint>`, where the hint names the enable toggle.
   - Run `python3 tools/max_verify_live.py --project simple-fm; echo $?`.
   - Expect: `Live check skipped: ...` with the toggle hint, the reminder line last, exit 2. No window opens in MAX.
   - Result: pending

2. [ ] Toggle ON, DSP OFF: a recorded patch
   - Turn the toggle ON and switch DSP OFF in MAX, then run `python3 tools/max_verify_live.py --project simple-fm; echo $?`.
   - Expect: `simple-fm.maxpat  [checked; record: record 3 s; note 60 100 into the notein]`, the note is audible, a `shot:` path and a `run dir:` line, no LIVE BLOCKER or LIVE WARNING, DSP OFF again afterwards, exit 0.
   - Read the shot PNG: is it the simple-fm window, with the two `send~ __maxbridge_L/R` taps under `dac~`?
   - Note the wall-clock time of the run (W3).
   - Afterwards `git status --porcelain patches/simple-fm` and `find patches -name '__maxbridge_*'` both print nothing.
   - Result: pending

3. [ ] Blockers and warnings
   - Run `python3 tools/max_verify_live.py patches/max-bridge/fixtures/fx-nosuchobj.maxpat patches/max-bridge/fixtures/fx-dc.maxpat; echo $?`.
   - Expect: fx-nosuchobj is load-only (`output not tapped`, DSP on during the load settle) with `LIVE BLOCKER: MAX console: osc~: No such object (x1)`; fx-dc records and shows `LIVE WARNING: record flag dc_offset` (and `silent`); exit 1. Note the seconds per patch (W3).
   - Result: pending

4. [ ] D-02: DSP on during the load settle (gen~ compile errors)
   - With DSP OFF, run `python3 tools/max_verify_live.py patches/max-bridge/fixtures/fx-genfail.maxpat --record 0; echo $?`.
   - Expect: `[checked; load-only: record disabled (--record 0); DSP on during the load settle (restored afterwards)]`, LIVE BLOCKERs for `can't assign to parameter g` and for `failed to compile` (genpatcher / patcher), DSP OFF again afterwards, exit 1.
   - Switch DSP ON and repeat the command.
   - Expect: the same blockers, and DSP stays ON afterwards.
   - Result: pending

5. [ ] D-01: an audio-input project stays load-only with DSP untouched
   - amplitude-follower has `adc~` at its top level (`scan_patch` on `patches/amplitude-follower/generated/amplitude-follower.maxpat` gives inputs True, `amplitude-follower.maxpat:obj-2`). Its output is not tapped (no `dac~` cord), so it never records; gen-eq has both an `adc~` and a tapped `dac~`.
   - With DSP OFF, run `python3 tools/max_verify_live.py --project amplitude-follower; echo $?`.
   - Expect: `load-only: record skipped: audio-input patch ...; DSP not switched on: audio-input patch ...`, and MAX's DSP indicator never turns on during the run.
   - Mute the mics or put headphones on. Run `python3 tools/max_verify_live.py patches/gen-eq/generated/gen-eq-test.maxpat; echo $?`, then the same with `--live-inputs`.
   - Expect: without the flag, load-only with DSP untouched; with `--live-inputs`, `record: record 3 s` and a `record` block in the JSON (`--json`).
   - Result: pending

6. [ ] An open original is skipped, never closed
   - Open `patches/simple-fm/generated/simple-fm.maxpat` in MAX, then rerun step 2's command.
   - Expect: `simple-fm.maxpat  [skipped]` with `LIVE NOTE: original is open in MAX ...`, no temp window opens, and your simple-fm window stays open.
   - Make an unsaved edit in simple-fm (move a box) and rerun. Is it still skipped? Paste the window title MAX shows (W2).
   - Close the original WITHOUT saving.
   - Result: pending

7. [ ] Abort when MAX stops answering mid-batch
   - With the toggle ON and DSP OFF, run `python3 tools/max_verify_live.py patches/max-bridge/fixtures/fx-clean.maxpat patches/max-bridge/fixtures/fx-dc.maxpat patches/max-bridge/fixtures/fx-badargs.maxpat --record 5; echo $?` and switch the toggle OFF during the first recording.
   - Expect: `Live check aborted: MAX stopped answering during fx-clean.maxpat ...`, `Not checked: fx-dc.maxpat, fx-badargs.maxpat`, exit 2, within one load-timeout or less (W4).
   - Afterwards: no `__maxbridge_` window is left open in MAX (close any WITHOUT saving), DSP is back as before, and `find patches -name '__maxbridge_*'` prints nothing.
   - Result: pending

8. [ ] Cleanup
   - Turn the toggle OFF, or close the bridge patch.
   - Result: pending
