CONTEXT.md locks the mechanism: a load snapshot plus a diff; direct `_raw` writes keep working; port sync with orphan return; x-rank port order. The choices below are Claude's discretion, or how the planner resolved details the lock leaves open. Each one was prototyped at 5fdc098e (PD-9).

**PD-1. Snapshot and diff (B5, S4).**
- **Constants.** Hoist the from_dict `_handled_keys` set to a module constant `_BOX_HANDLED_KEYS` (frozenset, same 13 keys: id, maxclass, text, numinlets, numoutlets, outlettype, patching_rect, fontname, fontsize, presentation, presentation_rect, patcher, saved_object_attributes). Hoist `_handled_line_keys` to `_LINE_HANDLED_KEYS` (source, destination, order, hidden, midpoints, color). from_dict and both to_dicts use them.
- **Box snapshot.**
  - from_dict sets `box._loaded = {"fontname": ..., "fontsize": ..., "extra_attrs": copy.deepcopy(box.extra_attrs)}`, right after it builds extra_attrs.
  - `Box.__init__` sets `self._loaded = None`. Readers use `getattr(self, "_loaded", None)`, because builder boxes come from `Box.__new__`.
- **Patchline snapshot.** `Patchline.__init__` sets `self._loaded` when `_raw is not None`: order, `bool(hidden)`, a deepcopy of midpoints, a deepcopy of color and a deepcopy of extra_attrs. Otherwise it is None.
- **Shared helper `_apply_extra_attrs_diff(d, current, old, handled)`:**
  - every key of `old` missing from `current` is popped from `d`;
  - every key of `current` not in `handled` that is new, or whose value differs from `old[key]`, is written with `d[key] = value`. An existing key keeps its position and a new key appends.
- **Box.to_dict round-trip branch.** Right after `d = dict(self._raw)` and BEFORE the existing overlays (rect, I/O, text, outlettype, presentation, patcher, saved_object_attributes), when a snapshot exists:
  - apply the helper with `_BOX_HANDLED_KEYS`;
  - for fontname and fontsize, when the current value differs from the snapshot: None pops the key; anything else is written.

  The overlays stay last and unchanged, so presentation and rect fields still win.
- **Patchline.to_dict round-trip branch.** Keep the source/destination overlay. When a snapshot exists, apply the helper with `_LINE_HANDLED_KEYS`, then the change-gated write rules in reference_data, then return. This replaces the unconditional color/midpoints overlay. With no snapshot, run today's code exactly.
- **Comparison rules.**
  - Always compare with the snapshot, never with `_raw`. That keeps unchanged 12 vs 12.0 and `[1,0]` vs `[1.0,0.0]` in their file representation.
  - Never rebuild `d`.
  - The creation branches are untouched.

**PD-4. Port sync (B7).**
- **Back-refs.**
  - `Patcher.__init__` and from_dict set `_parent_box = None`, `_parent_patcher = None` and `_port_sync_suspended = False`.
  - from_dict sets `inner._parent_box = box` and `inner._parent_patcher = p` on each inner patcher it builds. add_subpatcher sets them AFTER its own inlet/outlet loop, next to its `_inner_patcher` assignment. The embedded add_bpatcher does the same.
  - add_gen and rnbo get none. Their ports are `in N` / `in~ N` newobj boxes.
  - Read the back-refs with getattr defaults.
- **When a sync runs.** Only when the box's maxclass is `inlet` or `outlet`, sync is not suspended, the parent box is either `maxclass == "bpatcher"` or a newobj whose name is `p` or `patcher`, and the parent box is still in `_parent_patcher.boxes` (identity). Otherwise it is a no-op returning [].
- **Rank.** The rank is the index in `get_inlets()` / `get_outlets()` (stable sort by x, so ties fall back to array order). This is the same order as hooks._port_ranks.
- **`_sync_parent_ports_after_add(box)`** (called from builders add_box after the append). Grow only:
  - an inlet sets `numinlets = max(numinlets, inner inlet count)`;
  - an outlet, when the inner outlet count exceeds numoutlets, inserts `""` into a copy of outlettype at the new box's rank (clamped), pads or truncates to the new count, assigns it, and sets numoutlets.
  - It never shrinks a count and never removes a cord.
  - Why grow only: `add_bpatcher(embedded=True)` declares numinlets/numoutlets before its inner ports exist. An exact resync on the first add would silently drop a cord already made to a higher port, and add_box has no orphan return.
- **`_sync_parent_ports_after_remove(kind, rank)`** (called from remove_box). Exact:
  - an inlet sets numinlets to the inner count;
  - an outlet deletes the outlettype entry at the rank computed BEFORE removal, when the list is longer than the new count, then pads or truncates and sets numoutlets to the inner count.
  - Then it removes the `_parent_patcher.lines` with `dest_id == parent.id and dest_inlet >= numinlets`, or `source_id == parent.id and source_outlet >= numoutlets`, and returns them as orphan dicts (same 4 keys as EditResult.orphaned).
- **API.**
  - `EditResult` gains `parent_orphaned: list[dict] = field(default_factory=list)`: cords removed in the PARENT patcher.
  - `remove_box` now returns `EditResult(box=<removed box>, orphaned=<parent cords>, parent_orphaned=<same entries>)`. That is the locked "returned as orphans"; parent_orphaned gives one uniform field. This is backward compatible: no caller uses the old None.
- **replace_box.**
  - It sets `_port_sync_suspended` around its remove_box + add_box (try/finally), so a port-for-port replacement is not seen as a remove followed by an add, which would drop the cords of the top port.
  - Afterwards, a same-kind port replacement does nothing to the parent (replace_box keeps the old x, so the rank is unchanged).
  - A port replaced by a non-port, or by the other kind, gets the remove rule for the old kind (rank captured before removal), then the add rule for the new kind.
  - The parent cords go ONLY in `parent_orphaned`. `orphaned` keeps its meaning, cords in this patcher, because replace_box_safe rewires `orphaned` by id inside self and would KeyError on a parent cord.
- **Save gate.** No hooks.py change is needed: the gate already warns on removed cords and refuses port x-rank changes.

<threat_model>
Security config: enforcement on by default, with no ASVS level set (treated as level 1). This is in-process serialization over local JSON, with no network, auth, crypto or package installs. What matters:
- integrity of user-confirmed patches (no silent loss, no silent cord removal);
- isolation of the caller's data;
- no edits to frozen patches;
- git hygiene.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| .maxpat JSON -> Patcher.from_dict / to_dict | Patch files (generated or MAX-saved) are untrusted structure; any unknown key or representation must survive a no-op round-trip |
| Caller's dict -> Patcher | The caller keeps using its dict (save-gate baselines, tests); the model must not write through to it |
| Inner patcher -> parent patcher | Port edits inside a subpatcher now mutate the parent box and parent cords |
| Concurrent Claude instances -> git | Broad staging or stash can sweep in or strand another instance's work |
