**PD-1. F1: remove the status overlay (not "limit to UI pairs").**
- **Why.** The DB has 115 status-role outlets on 56 objects. The only UI owners are waveform~, live.adsrui, mc.live.gain~, playlist~ and spectroscope~, and copying their rect onto a 22 px flonum would hide a whole display. No status outlet forms a UI-control-plus-readout pair; that pair is `add_overlay_readout`'s job.
- **Change.**
  - `_ROLE_COMPANION_MAP["status"]` becomes `{"companion": None, "placement": None}`, so the map keeps its six keys.
  - Delete the overlay branch of `_place_companions` and its docstring text. Any placement other than "right" falls back to "right".
- **Result.** A status-fed flonum stays an ordinary row box below its source.

**PD-2. F2: footprints and control bands in `_position_component`.**
- **Control identification.** `_identify_ui_controls` keeps its rule: a `_UI_CONTROL_NAMES` source whose FIRST cord's target is in the same or the next row. It also returns that cord's `dest_inlet`.
  - A candidate whose target is itself a candidate is not extracted; iterate to a fixed point. It stays a row box.
  - Group the controls by target, ordered by inlet and then by box-array order.
- **Group geometry.**
  - Controls sit left to right from the target's x, each starting at least `h_gutter` after the previous control's rendered right edge.
  - group width W = sum of control widths + `h_gutter` * (n-1).
  - Bottom-aligned: control y = target y - gap - control height, where gap = `v_spacing * 0.5`.
- **Footprint of a row box B.** Offsets relative to B's top-left:
  - left = min(0, rider lefts);
  - right = max(rendered w, W_B, rider rights);
  - above = max(H_B + gap if B has a group, -rider tops), where H_B is the tallest control;
  - bottom = max(rendered h, rider bottoms).

  Task 2 builds footprints from controls only; Task 3 adds riders.
- **Lines.** For each row, compute each box's ideal x with the unchanged `_target_x_for_inlet_align` / center logic (row 0 packs left to right).
  - slot left = ideal x + left, clamped to at least start_x, and at least the previous slot's right + `h_gutter`.
  - With grid_snap, round the box x UP to the grid, so the final snap leaves x unchanged and gutters survive.
  - **Wrap (PD-6).** When a slot would end past start_x + `options.max_width` and its line already holds a slot, open a new line and pack the rest of the row left to right from start_x. A slot wider than the cap sits alone on its line; the loop always advances.
- **Vertical.** Per line, band = max `above`. Box y = cursor_y + band; round it UP to the grid when band > 0 and grid_snap is on.
  - line height = max `bottom`.
  - next cursor_y = box y + line height + `v_spacing`, plus `(line height - 100) * 0.1` when line height > 100 (the existing adaptive gap).
  - With no controls, the geometry equals today's row spacing.
- **Then** place the controls at their group positions (x rounded up to the grid). `_place_ui_controls`' stacking at target x is gone.

**PD-3. F3: contrast after layout, plus decoration anchors.**
- **Order.**
  - `apply_auto_styling(patcher, *, contrast=True)`; the default keeps today's behavior for direct callers.
  - `finalize_patch(is_new=True)`: `apply_auto_styling(patcher, contrast=False)`, then `apply_layout(patcher, force=force_layout)`, then `ensure_text_contrast(patcher)` exactly once, then `populate_assistance_comments()`.
  - Measured: the order fix alone removes the evidence patch's 1.67:1 warning, but the panel still lands at (300, 30) while its chain sits at x=30. Anchors are needed too.
- **Capture before layout.** Run this in each apply_layout call, on that patcher's boxes, before `_find_components`.
  - **Decorations** are boxes with no cords that are one of:
    - a panel (maxclass panel);
    - an untargeted comment (`target_id` None);
    - a non-panel box with `extra_attrs["background"] == 1` (step markers).
  - **Content** is every other box that is not a comment.
  - **Box anchor.** A non-panel decoration anchors to the content box with the smallest rendered-rect gap. The gap is max(horizontal gap, vertical gap), 0 when overlapping; ties go to the smaller other-axis gap, then box order. The gap must be at most `_ANCHOR_GAP` = 40 px. Store the offset (dx, dy) from the anchor's top-left.
  - **Panel anchor.** Otherwise, if its rendered center lies inside a panel that has members, it anchors to the smallest such panel, with the offset from the panel's top-left.
  - **Unanchored** decorations stay in the disconnected placement, as today.
  - **Panel members** are content boxes whose rendered-rect center lies inside the panel's patching_rect. The tracked set is the members plus the riders box-anchored to a member.
  - **Pads** = each panel edge minus the tracked set's pre-layout bbox edge, clamped to at least 0. A panel with no members stays an unanchored decoration.
- **Placement.** `_place_decorations` is one idempotent function:
  1. Each box-anchored rider goes to its anchor's position + offset.
  2. Each panel is refit to its tracked set's bbox + pads.
  3. Each panel-anchored rider goes to its panel's position + offset.

  Decorations are never grid-snapped. It runs twice:
  - **Provisional,** inside each component pass, for that component's riders and for panels whose tracked set lies wholly in the component. The block bbox then includes them: translate the block right or down if they reach left of cursor_x or above the band top, and advance cursor_x past them.
  - **Final,** for all decorations, after `_snap_to_grid` and the port-order restore and before midpoints, so offsets are exact against final positions.

  Riders of disconnected boxes are reserved in the disconnected footprints.
- **Safety net.** If any box ends with x or y below 0, translate every box, and every existing midpoint, by the deficit.
- **Footprints.** A rider's offset rect extends its anchor's footprint (PD-2). A label beside a control extends that control's footprint and hence the group width, so labels do not land on row neighbours.
- **Midpoint routing.** `_boxes_between` and `_route_clear_path` skip panels and boxes with `background == 1` as obstacles. Once panels sit behind their chains, every enclosed cord would otherwise see the panel as an unavoidable obstacle and lose routing. This keeps F3 from regressing cords.

**PD-4. F4.** The apply_layout recursion skips a box whose maxclass or name is `bpatcher`. The `_skip_auto_layout` opt-out is still honoured, and `p` subpatchers still recurse.

**PD-5. F5 guard.**
- **MAX-saved.** `is_max_saved(props)` (sizing.py) is True when `props["appversion"]` is a dict whose (major, minor, revision) differs from `DEFAULT_PATCHER_PROPS["appversion"]` (9, 0, 0). Missing or non-dict means False.
  - It takes a Patcher.props dict or a raw patcher dict.
  - Evidence: the generator always writes 9.0.0. The corpus has 42 MAX-saved files (9.1.2 / 9.1.5) and 15 at 9.0.0. Max 9.2 writes revision 0, so revision alone is not enough.
- **Large.** More than `LAYOUT_MAX_BOXES` = 120 boxes in the patcher being laid out (its own top-level boxes).
- **Behavior.** `apply_layout(patcher, options=None, *, force=False)` checks both at entry, before any mutation, and raises `LayoutRefusedError(ValueError)` with the text in `<reference_data>`.
  - The recursion passes `force` down, so inner patchers are checked too.
  - `finalize_patch(patcher, is_new=True, *, force_layout=False)` passes it through.

**PD-6. F5 width cap.**
- **Constants.** `LAYOUT_MAX_WIDTH = 1600.0` (the memory's "~1600px" cap) and the field `LayoutOptions.max_width: float = 1600.0`. cap_right = `_START_X + max_width`.
- **Rows** wrap (PD-2).
- **Component banding.** After a component block is positioned (provisional decorations included), if its right edge > cap_right and cursor_x > `_START_X`, translate the whole block to (`_START_X`, band bottom + `_COMPONENT_GAP`). That position is the new band top. Track band bottom as the max block bottom.
- **Disconnected group.** It starts at cursor_x when cursor_x + its widest footprint <= cap_right; otherwise at (`_START_X`, band bottom + `_COMPONENT_GAP`). Inside `_position_disconnected`, a new column that would end past cap_right instead starts a new column band at the group's left x, below the tallest column so far.

**PD-7. rendered_rect and MAX-saved message widths.**
- **Signature.** `rendered_rect(box, *, max_saved=False)` in sizing.py, with the constants in `<reference_data>`.
- **Messages** use the fix plan's and CLAUDE.md's `len*8+25`, measured on the longest line. A multi-line `;` message otherwise reads as hundreds of px wide.
- **max_saved.**
  - Evidence: the 653 font-12 message boxes in the bundle's max help are 97.7% narrower than `len*8+25` (median -35 px). MAX normalizes geometry when it saves.
  - Literal application on the corpus adds 77 overlap warnings on user-confirmed MAX-saved files, against 4 with max_saved.
