## Behavior changes (regression check)

**New boxes:**
- `add_box` of the 14 non-UI live.* names now writes newobj + text, sized to the text, with DB I/O (live.thisdevice is 1 in / 3 out).
- `add_box("p"|"patcher")` raises ValueError naming `add_subpatcher`. `add_subpatcher` is unchanged.
- `add_box("markup"|"progress")` raises ValueError ("UI maxclass ... Rule #1"), because neither has a DB entry.
- 16 widgets that used to come out as wrong newobj boxes now build with their own maxclass and bundle-median sizes.
- All refusals run before an id is consumed. Refused `replace_box`, `replace_box_safe` and `insert_into_connection` calls leave boxes, cords and `_next_id` untouched.

**Validation and save gate:**
- An own-maxclass box of a removed live.* name, or a maxclass-`patcher` box without an embedded patcher, is now an objects-layer "Wrong maxclass" error, and it blocks a save.
- MAX-saved patches containing the 18 widgets no longer get "Wrong maxclass" or "Unknown object".

**Unchanged and side effects:**
- Loaded and round-tripped patches serialize exactly as before (69/69).
- `suggest_subpatchers` now treats builder-made subpatcher boxes (name `patcher`) as eligible, as loaded `p` boxes already were. Normalized output on committed patches is unchanged.
- `tools/sync_max_bundle.py` prints one more summary line (`ui maxclasses`) and adds the `ui_maxclasses` JSON section, last in SECTION_KEYS.

**Rewritten tests.** Each of these encoded C4's wrong behavior; none was deleted.
- test_sizing `TestLiveObjectSizes`:
  - `test_all_live_in_ui_maxclasses` became `test_live_ui_widgets_in_ui_maxclasses` plus `test_non_ui_live_objects_are_newobj`;
  - `test_visual_widgets_have_fixed_sizes` changed data only (live.banks and live.colors dropped);
  - `test_non_visual_have_none_in_ui_sizes` became `test_non_ui_live_objects_not_in_ui_sizes`.
- test_analysis `test_nesting_depth` and `test_nested_subpatchers`: one line each now uses `_quick_box`.
