<objective>
Implement Q13 of `.planning/reviews/2026-10-11-fix-plan.md`. It covers review findings C4 and C5, which fix the UI maxclass set.

- **C4: non-UI names in the UI set.** `UI_MAXCLASSES` lists 14 non-UI `live.*` objects and `patcher`. `add_box("live.thisdevice")` therefore writes `{"maxclass": "live.thisdevice"}` with no `text`, and `add_box("p", ["foo"])` writes `{"maxclass": "patcher"}`. MAX cannot load either, and the maxclass validator can't catch them because the names are whitelisted. Q13:
  - removes the 15 names from `UI_MAXCLASSES` and `UI_SIZES`;
  - makes `add_box("p"|"patcher")` raise and point to `add_subpatcher`;
  - lets the maxclass check flag own-maxclass boxes of these names.
- **C5: real UI maxclasses are missing.** 18 widgets MAX saves with their own maxclass are missing, so `add_box` writes them as newobj and the validator raises "Wrong maxclass" on MAX-saved help patches. Q13 adds them after bundle verification and gives them bundle-derived default sizes. `markup` and `progress` have no DB entry, so `add_box` refuses them rather than guess their I/O (Rule #1).
- **C5 tooling.** A report-only `ui_maxclasses` section in `tools/sync_max_bundle.py` regenerates the set from a bundle survey after every Max update.

Purpose: generated LOM devices (live.thisdevice/live.path/live.object) currently fail to load in MAX, and MAX-saved patches containing common widgets are blocked by a false "Wrong maxclass" error.

Output: three commits, one per task, each with `(Q13)` in the message. The task dir also gets two untracked confirm patches for the user to open in MAX. Nothing is pushed.
</objective>

<planner_decisions>
These are decisions the fix-plan does not spell out. They are recorded here so the executor does not need to stop.

1. **"Verified against bundled files" means box-level maxclass.** A candidate counts when at least one bundled `.maxpat`/`.maxhelp` box, at any patcher depth, has `"maxclass": "<name>"`, and no newobj box has the name as its first text token.
   - All 18 pass, so none is left out.
   - 7 of them appear only inside help-tab subpatchers (depth >= 1), the usual help-file layout: live.adsrui, itable, multirange, gridmeter~, node.codebox, text.codebox, zplane~. SUMMARY lists them with their evidence files.
2. **`markup` and `progress` join the set, but `add_box` refuses them.** Neither has a DB entry or a refpage (`progress` ships only `externals/max/progress.mxo` and `help/max/progress.maxhelp`).
   - The validator needs them in the set: they cause 22 of the 40 "Wrong maxclass" errors plus 22 "Unknown object" warnings.
   - Building them would fall into Box's "UI object not in database" path, which guesses 1 in / 1 out, while MAX says progress is 1 in / 0 out. That would break Rule #1.
   - So `_require_buildable` refuses any UI_MAXCLASSES name that `db.exists()` doesn't know. Today that is exactly these two names.
3. **The maxclass-usage check stops exempting `patcher`** (`_MAXCLASS_USAGE_SKIP = {inlet, outlet, bpatcher}`). This is C4's "the maxclass validator can't catch it" half.
   - MAX never writes maxclass `patcher` (0 of 3,139 bundle files).
   - No committed or fixture patch has one, and triage is identical in the prototype.
   - `_STRUCTURAL_MAXCLASSES` keeps `patcher`, so Layer 2 name extraction is untouched.
4. **UI_SIZES defaults for the 18** use the per-axis median of the MAX-saved `patching_rect` width and height, rounded to 0.1. The mode is ambiguous for several names. `markup` is None (text-bearing, like comment). Without entries these widgets would get text-width boxes; for example jit.pworld would be ~86x22 instead of 640x360.
5. **The sync section is report-only.** The tool's write contract allows DB object files only, so it never writes `maxclass_map.py` or `sizing.py`.
6. **Not fixed; surfaced in SUMMARY (rule 7):**
   - `colorpicker` is in the UI set, but MAX writes it only as newobj (3 boxes, 0 own-maxclass). It is the sync section's single `newobj_only_in_bundle` entry.
   - The 27 other bundle maxclasses outside the set.
   - Package-gated UI names bypass `allowed_packages` with guessed I/O: bach.roll and dada.bounce today, and live.adsrui once it is added.
   - `m4l_polish.organize_push_banks` writes `maxclass: "live.banks"`, which is now a true-positive "Wrong maxclass". Q15/D5 owns it.
   - The G8 empty-text crash belongs to Q19.
