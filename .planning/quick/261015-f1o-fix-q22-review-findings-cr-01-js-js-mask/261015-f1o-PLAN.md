**Claude's discretion, decided here** (record each in SUMMARY):
- **Value ends.** A closing `'`, `"`, backtick or regex `/` also counts as a value end, so a following `/` is division. This follows the JS grammar, where a literal ends an expression.
- **`}` is not a value end.** A `/` after it starts a regex, per the D-02 rule. Damage from a misread division is bounded because an unterminated regex ends at its line end.
- **Prefix keywords.** The set is `_JS_REGEX_PREFIX_KEYWORDS` = return, typeof, instanceof, in, of, new, delete, void, throw, case, do, else, yield, await. Matching is on the whole identifier that ends at the previous significant character, so `returned / 2` is division.
- **Line ends.** An unterminated regex ends at its line end, because a JS regex literal cannot span lines. It does not run to EOF, unlike strings and comments.
- **Delimiters.** The regex delimiters and flags stay in the mask; only the body is blanked.
- **Known limit.** A `)` that closes an `if`/`while`/`for` header directly before a regex literal reads as division. This is the standard heuristic's limit; list it in SUMMARY.
- **Existing fixtures.** The two existing Check 15 fixtures gain an `h = y;` line (see `<rules>`).
</decisions>
