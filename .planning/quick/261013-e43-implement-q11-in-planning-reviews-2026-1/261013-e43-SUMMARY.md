## Deviations from Plan

1. **[Rule 1 - Test precision] No-placeholder-clobber test narrowed to real base text.** The `<behavior>` wording ("base digest non-empty -> merged digest not a placeholder") failed on 35 ports. On all of them the *domain file itself* carries the placeholder "Control output" (e.g. jit.*, array.at, M4L.api.ObserveTransport), so the merge correctly keeps the base value. The test now counts a clobber only when the base digest is real text (not in OVERRIDE_PLACEHOLDER_DIGESTS). The intent, that placeholders never replace real text, is unchanged. Commit `ec390d8`.
2. **Placement of new overrides keys.** The plan did not specify where the new entries go. bp.arc.accum-2 and bp.arc.knob are inserted at the end of the `_domain_packages` group (before `_domain_other`). jweb~ (base domain Max) goes at the end of the `_domain_max` group (before `_domain_msp`). No other key moved.
3. **Ledger/gate mechanics.** The worktree sandbox refused compound shell lines that combine `git` with other commands, and `git rev-parse --git-dir` redirection. So:
   - every verify gate ran as its separate parts: the same python assertions verbatim, then `git status --porcelain` -> pytest -> `git status --porcelain` with a diff;
   - the commit ledger is `base-sha.txt` (45f23b4) instead of the git-dir ledger file.

   All gate assertions passed as written.
4. **`_audit` box counts not in `<evidence>`.** I filled these from the base-sha help-io baseline:
