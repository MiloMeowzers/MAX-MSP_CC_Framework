3. **Cold inlet = DB `hot is False`.**
   - Unknown objects never have cold inlets (abstractions route inlets independently).
   - For a `variable_io` object, an inlet beyond the DB list takes the last DB inlet's flag when the DB lists 2 or more inlets (pack: cold). When the DB lists only inlet 0 (expr, vexpr, if, sprintf), every inlet above 0 is cold.
   - This reads "cold inlets" literally and keeps groove~-style MSP float inlets out (CLAUDE.md Rule #3).
4. **Trigger-order exclusions** = the spec's gate/switch/poly~/js/p, plus `_ALL_HOT_NAMES` (js/jsui/v8/v8ui/v8.codebox/node.script/node.codebox/p/patcher/bpatcher/poly~/mc.poly~/pfft~/rnbo~/gen~/mc.gen~), plus:

   Without the gate and poly~ exclusions, the committed sample-layers-slot (`trigger s s b` into gate) and scala-synth (`trigger b b i` into poly~) would block. Both are correct.
5. **One hop.** A trigger outlet reaches a hop only at the hop's inlet 0, then follows the hop's outlet 0 to any (box, inlet). A cold-inlet feed into a hop emits nothing.
   - Hops: maxclass `message`; names `zl.reg`, `zl` whose first argument is `reg`, `f`, `float`, `i`, `int`, `prepend`.
   - Exactly one hop. The destination is never the trigger itself.
   - When one outlet feeds both the hot and a cold inlet, the fan-out critic owns it. The trigger-order check flags only when min(hot outlets) > min(cold outlets).
6. **`$N` atom counts.** Any other case is unknown, and an unknown feeder means no finding. Counts are resolved in this order:
   - (a) A trigger/t outlet takes its argument letter: `b` = 0; `i`, `f`, `s`, a number or another symbol constant = 1; `l` = unknown. Arguments starting `#` or `$` are unknown, an argument-less `t` acts as `i i`, and an outlet past the argument count is unknown.
   - (b) Otherwise, for a non-`variable_io` DB object, the outlet's DB entry: `type` `bang` or `signal_role` `trigger` = 0; `type` int/float/symbol or `signal_role` float = 1.
   - (c) Otherwise the box's own MAX-saved `outlettype` at that index: `bang` = 0, `int`/`float` = 1.

   (c) is discretion beyond "use the DB outlet types". The DB types loadbang, button and metro outlets as plain `control`, so without (c) the bang = 0 case almost never fires. MAX writes `outlettype` itself at save. Planning measured 0 hits on 3139 bundle files and 69 committed files with (c) on.
7. **`$N` multi-feeder (assumption delta, discretion).**
   - `$N` is the regex `(?<!\\)\$([1-9])` on the message box text; Max substitutes `$1`..`$9`.
   - Flag only when every inlet-0 feeder is known and their maximum is below the highest N, and nothing feeds inlet 1 (a `set` there replaces the text).
   - Evidence: message.maxref.xml says each incoming number "replaces the value stored in the argument $1" and a bang "sends out the contents". So a bang beside a value feeder is the resend idiom. Under a per-cord reading, all 72 bundle hits were that idiom; under this rule there are 0.
8. **Trigger-type scope.**
   - Flag any single lower-case ASCII letter other than b, i, f, l, s. trigger.maxref.xml lists only i, f, b, l, s; every other symbol is a constant.
   - That covers `a` (spec), PD's `p`, and typos. 0 hits in the bundle and committed files.
   - Skip upper case (Max behaviour not documented), `@`/`#`/`$` tokens and multi-character constants.
   - One blocker per distinct invalid token per box.
9. **Scope and wiring.**
