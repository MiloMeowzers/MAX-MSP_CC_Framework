<planner_decisions>
These are decisions the fix plan does not spell out, recorded so the executor does not need to stop.

1. **New apply mode `groups`; the bare `--apply inherited` is left alone.** Q14 says "extend the `--apply inherited` path". The extension is a sibling mode in the same tool, sharing its scan and group-page definitions. `test_apply_needs_an_explicit_attribute_list` pins `--apply inherited` without `--attributes` to exit 2, so reusing that form would regress it. Record this deviation in SUMMARY.
2. **Storage is one new file, `.claude/max-objects/groups.json`**, merged at call time (Q14's stated preference).
   - Copying the names into domain files would add about 8,605 message names and 2,051 attribute names across ~420 entries, roughly doubling `mc/objects.json`.
   - Canonical serialization is `json.dumps(data, indent=2, sort_keys=True, ensure_ascii=False) + "\n"`.
   - Top-level keys:
     - `_comment` (fixed text: written only by `tools/sync_max_bundle.py --apply groups`, merged by `ObjectDatabase.messages/attributes/selectors`, never copied into domain files);
     - `max_version` (the install's `short_version`);
     - `attribute_definitions` (`{attr: {"definition": {type,get,set}, "source": path relative to C74}}`);
     - `profiles` (`{id: {"family", "messages", "attributes", "source"}}`);
     - `members` (`{db_key: [profile ids]}`).
   - Families and ids:
     - `mc`: from `<mcwrapper>` children; source `refpage <mcwrapper>`.
     - `jit`: from `<jittermethodlist>` + `<jitterattributelist>`; source `refpage <jittermethodlist>/<jitterattributelist>`.
     - `thispatcher`: fixed id `thispatcher-help`; source `help/max/thispatcher.maxhelp`, relative to C74.
     - The `mc` / `jit` id is family + `-` + the first 8 hex of the sha256 of `json.dumps({"attributes": sorted, "messages": sorted}, sort_keys=True)`. Two different profiles of one family sharing an id raises RuntimeError.
     - Names inside a profile are sorted and deduplicated. Member profile lists are sorted.
3. **Membership comes only from the per-object refpage lists, never from the `mc.` / `jit.` name prefix.**
   - Members are iterated from `classify_refs(...)["authoritative"]`, skipping `_is_doc_page` refs, and resolved with `_muted_lookup` + `locate_base_entry`. The member key is the DB key that function returns.
   - A ref with a non-empty group list that does not resolve is reported in `unresolved` (research probe: 0) and skipped.
4. **`attribute_definitions`** keeps only names that some member's attribute list references, taken from `group_attribute_definitions(index)`.
   - Ambiguous names (`name`) are left out.
   - Snapshot Messages (`snapshot-group`) is referenced by no per-object list, so it is out of scope. Note it in SUMMARY.
   - Undefined names keep no type. They stay in the profile `attributes` list and so reach `selectors()` only.
5. **Additivity across bundle updates.** `compute_groups` unions each existing member's names, per family, from the groups.json already on disk into the target before hashing. `check_groups_additive(old, new)` is the guard:
   - no member is removed;
   - a member's effective name set (the union of its profiles' messages and attributes) never shrinks;
   - an existing `attribute_definitions` entry never changes;
   - `max_version` and `_comment` may change, and orphan profiles may be dropped.
6. **ObjectDatabase accessors are read-only merges.**
   - `lookup()` is unchanged, and inherited data is never written into `_objects`. `compute_deltas` detects override shadowing by comparing resolved and raw messages, so mutating `_objects` would flag every member as shadowed.
   - `messages(name)` = own `messages` (the override list where one exists, e.g. mc.sig~) + profile messages, deduplicated in order.
   - `attributes(name)` = deep copy of the own `attributes` dict + inherited names that have a definition. Own entries win.
   - `selectors(name)` = set(messages) ∪ own attribute names ∪ every inherited attribute name. Q23 should use `selectors()`, since MAX accepts attribute names as messages.
7. **thispatcher source = help/max/thispatcher.maxhelp**, not the user-guide JSON Q14 names. That JSON only covers max/dsp/midi/jitter app messages; its wclose is the DSP window. The user guide's scripting overview defers to the thispatcher help file. Script subcommands and window flags are not stored (research open question 1, deferred). Record both points in SUMMARY.
8. **compute_inherited** takes an optional `groups` dict. A name recorded in a member's groups.json profiles counts as recorded, so it is neither pending nor undefined. With no groups.json, behaviour is unchanged (the existing TestInheritedAttributes cases pin this).
9. **Security:** ASVS L1, block on high; see `<threat_model>`. No package installs.
</planner_decisions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Max bundle refpages/help -> groups.json | Bundle XML/JSON decides which names become legal under Rule #1 |
| Sync tool -> DB tree | A new writer can create one file inside `.claude/max-objects/` |
| groups.json -> ObjectDatabase consumers | Every patch builder/validator constructs ObjectDatabase; load errors are global |
