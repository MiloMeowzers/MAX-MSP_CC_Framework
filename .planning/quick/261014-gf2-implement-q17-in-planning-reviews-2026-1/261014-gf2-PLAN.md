**Validator (src/maxpat/validation.py):**
- `ValidationResult(layer, level, message, auto_fixed=False, proposed_removal=None)`. The docstring lists levels "error", "warning", "info", "fixed". Only error, warning and info are emitted ("info" at the domain layer and in code_validation.py). Verify that nothing emits "fixed".
- Layers: json (errors stop the pipeline), objects, maxclass, packages, community, connections, domain, domain restrictions, embedded GenExpr.
- Unknown object: `"Unknown object: '<name>' -- not in database"` at level **warning**. A PD object is an **error**. An rnbo/gen-only name outside its scope is an **error**. A domain-restriction violation is an **error**.
- Invalid cords come back as **error** with `proposed_removal = (src_id, src_outlet, dst_id, dst_inlet)`. `validate_patch` never mutates its input. `apply_fixes(patch, results)` is the only remover; it returns the matched keys, and you re-validate afterwards. signal_role mismatches are warnings.
- `has_blocking_errors(results, is_new=True)`: only errors count. An error with a proposal blocks only when `is_new`. A legacy `auto_fixed` error without a proposal does not block. Every other error blocks.

**Critics (src/maxpat/critics/):**
- `CriticResult(severity, finding, suggestion)` with severity blocker / warning / note.
- `review_patch` always runs dsp, structure and layout. It runs rnbo when an rnbo~ box is present, m4l when plugin~ / plugout~ / live.thisdevice is present, external when `ext_code` is given, and package when package objects are present.
- package_critic.py emits warning ×3, note ×1 (Bach llll, Q3) and blocker ×1 ("Object not installed", `verified_installed: false`).

**Save gate (src/maxpat/hooks.py `_blocking_findings`, `_gate_report`, `_run_save_gate`):**
- Blocking set: validator errors (proposed removals included; legacy auto_fixed without a proposal excluded) plus critic blockers, run on deepcopies with one cached DB.
- Baseline: `original_text`, else HEAD, else the file on disk. With none, the file is new and every blocker refuses. Findings are matched by a key of rule template plus box ids, as a multiset.
- A changed port x-rank refuses. Removed cords → one `SaveGateWarning`, never a refusal. `force=True` saves with a `SaveGateWarning`.
- `PatchValidationError` carries `.findings`, `.port_changes` and `.path`. `StaleFileError` is raised before the gate when `original_text` no longer matches the disk.
- `write_js` is report-only and never gated. `write_gendsp` runs the same gate.
- CLAUDE.md Rule #7 says the gate checks top-level findings only, while removed cords and port ranks are walked recursively. Confirm this in the code.
