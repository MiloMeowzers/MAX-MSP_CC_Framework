<planner_decisions>
These are decisions the fix plan does not spell out, recorded so the executor does not need to stop.

1. **ModMode semantics stay ABSOLUTE for the gen synth skeleton.** Its docstring and tests intend Absolute. The bug was that the wrong enum serialized it as 3 (Additive). With the fixed enum it serializes as 4. The kicksynth-m4l ground truth used 0 (None). Do not switch to NONE and do not add `parameter_modrange`: the report decides neither. Flag both points in SUMMARY for the user to judge in Live.
2. **UnitStyle values do not change.** The refpage order (Int, Float, Time, Hertz, deciBel, %, Pan, Semitones, MIDI, Custom, Native) matches the existing 0-9. The bundle parity test pins it. Do not add NATIVE=10, since nothing uses it (note it in SUMMARY).
3. **"DB-driven parameter-capable set" is implemented as a refpage-grounded constant plus a `requires_max` parity test.** The object DB has no parameter-capability field: `db.attributes()` carries `parameter_enable` only for live.arrows. Adding a schema field is outside Q15. The ground truth is the `<parameter />` element in m4l-ref refpages: exactly the 13 live.* names in the must-haves (Max 9.2.0). `LIVE_PARAMETER_OBJECTS` replaces the negative `_LIVE_NO_PARAM` list (its only users are m4l_polish.py:25/133 and m4l_critic.py:350/385/428; no test imports it) and stays in `src/maxpat/critics/m4l_critic.py`, where `_LIVE_NO_PARAM` lived. `mc.live.gain~` also carries `<parameter />` but is outside the `live.` prefix scan both modules use. Leave it out and note it in SUMMARY.
4. **Class-aware polish defaults (D1 "m4l_polish defaults" + D5 "no parameter attributes on non-parameters").** `ensure_parameter_enable` used to `setdefault` `parameter_type` FLOAT and `parameter_unitstyle` FLOAT on every live.* control. After the enum fix that would make a live.tab/menu/text/toggle/button a Float parameter. Bundle evidence (help/example patches, Max 9.2.0):
   - live.tab is saved as type 2 in 328/328, live.menu 366/369, live.text 1608/1624, live.toggle 732/735, live.button 218/268;
   - live.dial is type 0 in 1447/1657, live.numbox 884/1090, live.slider 34/51, live.gain~ 444/445;
   - live.grid and live.step are type 3.
   So the type/unitstyle defaults are written only for `_FLOAT_NATIVE_LIVE_CLASSES = {live.dial, live.numbox, live.slider, live.gain~}`. Other parameter-capable classes get `parameter_enable` and an empty `saved_attribute_attributes.valueof` dict (naming needs it) but no type, so MAX's class default applies. Existing values are never overridden (D-01).
5. **Push bank storage.** `patcher.parameters.parameterbanks` uses the MAX-saved shape from the bundle (`clippings/Live API Snippets/Device.DeviceParameterMap.maxpat`): string keys "0".."n-1", each `{"index": i, "name": <bank name>, "parameters": [8 entries, "-" = empty slot]}`. Slot entries remain parameter longnames: the `live.banks` refpage `new`/`edit` methods take parameter names.
   - Overwrite rule: write when `parameterbanks` is absent or every slot of every bank is "-" (MAX's default placeholder is `{"0": {"index": 0, "name": "", "parameters": ["-" x 8]}}`). Otherwise leave it untouched (D-01). This also makes re-polish idempotent.
   - Other keys under `patcher.parameters` (per-object entries such as `"obj-20": [...]`, `inherited_shortname`) are preserved.
   - The live.banks box is still created or reused, because `_check_missing_live_banks` keys on it. Any stale `_parameter_banks` key on an existing live.banks box is removed, because it is this module's own invalid artifact.
   - **live.banks box form (D5 fix).** The bundle's `help/m4l/live.banks.maxhelp` saves live.banks as `{"maxclass": "newobj", "text": "live.banks", "numinlets": 1, "numoutlets": 1, "outlettype": [""]}`. `UI_MAXCLASSES` (maxclass_map.py:65) excludes it.
     - The current `maxclass: live.banks` box makes `save_patch_roundtrip` refuse a polished device ("Wrong maxclass ... live.banks"), which blocks the Live check, so new boxes use the newobj form.
     - Finding an existing box accepts either form via `get_box_name(box) == "live.banks"` (src/maxpat/utils.py). An existing legacy-form box is reused as-is, not converted.
     - `_check_missing_live_banks` in the critic switches to the same `get_box_name` test.
6. **Prefix renaming is consistent or it does not happen.** The rename is per name. A name is renamed only when every occurrence is in a position the pass can rewrite; otherwise it is reported. coll and dict stay prefix targets: they were before, `test_all_named_object_types` pins it, and every `coll X` / `dict X` box with one name is renamed together. External code or patchers (js/v8/node.script/jsui/v8ui files, poly~/pfft~ voice files, non-embedded bpatchers, abstractions unknown to the DB) cannot be scanned, so their presence makes every candidate report-only. Conservative false blocks (e.g. a `route level` beside `s level`) are acceptable: they are reported, never broken. Precise rules are in Task 3.
7. **The report channel** is a new pure function `plan_m4l_prefixes(patch_dict, db=None) -> {"rename": [sorted names], "report_only": {name: reason}}` plus one `UserWarning` from `ensure_m4l_prefixes` when `report_only` is non-empty. The signatures and return values of `ensure_m4l_prefixes` and `polish_m4l_device` are unchanged (`test_polish_returns_patch_dict`).
8. **The Live confirmation is not an executor task.** Task 3 writes a ready-to-paste check device into Q, and SUMMARY lists the checks as pending user confirmation.
9. **Security:** ASVS L1, block on high; see `<threat_model>`. No package installs.
