## What changed

- **D1 enums** (`m4l_constants.py`):
  - `ParamType` is FLOAT=0, INT=1, ENUM=2, BLOB=3.
  - `ModMode` is NONE=0, UNIPOLAR=1, BIPOLAR=2, ADDITIVE=3, ABSOLUTE=4.
  - The docstrings cite parameters.maxref.xml and kicksynth-m4l 408cdf8.
  - UnitStyle values are unchanged; the refpage order confirms them.
- **D3 stereo** (`add_m4l_gen_synth`): a bare `plugout~` (2 inlets). gen~ outlet 0 is wired to inlets 0 and 1.
- **D3 gen~ inlet** (`add_gen`): the parent gen~ gets `numinlets = max(1, num_inputs)`. The inner patcher is unchanged: no `in` boxes, and the codebox keeps 0 inlets.
- **D5 banks** (`organize_push_banks`):
  - Banks are written to `patcher.parameters.parameterbanks` as `{"0": {"index", "name", "parameters"[8]}}`. This happens only when the key is absent or holds MAX's all-`-` placeholder.
  - Sibling keys and user-defined banks are preserved.
  - A stale `_parameter_banks` on an existing box is popped.
  - A new live.banks box is a newobj.
- **D5 parameter set** (`m4l_critic.LIVE_PARAMETER_OBJECTS`):
  - It replaces `_LIVE_NO_PARAM`, which is removed with no alias.
  - polish collection and all three critic checks use it.
  - `_check_missing_live_banks` detects live.banks through `get_box_name`, so both forms count.
- **D2 prefixes** (`plan_m4l_prefixes` + `ensure_m4l_prefixes`): implemented to the rules in planner decision 6 / Task 3. The signatures and return values of `ensure_m4l_prefixes` and `polish_m4l_device` are unchanged; `ensure_m4l_prefixes` gained an optional `db=None` keyword.

## Decisions taken (planner decisions 1-7)

1. **ModMode stays ABSOLUTE for the skeleton.** It now serializes as 4 instead of 3 (Additive). No `parameter_modrange` was added. kicksynth-m4l used None (0); this is a judgment call for the user in Live.
2. **UnitStyle is unchanged** (0-9), and the bundle parity test confirms it. NATIVE=10 is not added because nothing writes it.
3. **The parameter-capable set is a refpage-grounded constant, not a DB field.** The DB has no parameter-capability field. `LIVE_PARAMETER_OBJECTS` holds the 13 live.* classes whose Max 9.2.0 m4l-ref refpages carry `<parameter />`. `test_set_matches_refpages` (requires_max) pins it.
4. **Class-aware polish defaults.** Float type and unitstyle are written only for live.dial, live.numbox, live.slider and live.gain~. live.tab, menu, text, toggle, button, grid, step, drop and arrows get `parameter_enable` plus an empty valueof, so MAX's class default applies. Existing values are never overridden.
5. **Push bank storage** is MAX's `parameterbanks` shape. The overwrite rule is "absent or all-placeholder", which makes re-polish idempotent.
   - **live.banks newobj form:** found at planning, not named in the review. The old `maxclass: "live.banks"` box made `save_patch_roundtrip` refuse a polished device ("Wrong maxclass"), which blocked the Live check.
   - New boxes now use `maxclass: newobj, text: live.banks`, the form in `help/m4l/live.banks.maxhelp`. Existing boxes in either form are reused as-is.
6. **Prefix renaming is consistent or it does not happen.** coll and dict remain prefix targets. Any external code or patcher makes every candidate report-only. Conservative false blocks are accepted: a name is reported, never broken.
7. **Report channel:** the pure `plan_m4l_prefixes(patch_dict, db=None)` plus one UserWarning from `ensure_m4l_prefixes`.
